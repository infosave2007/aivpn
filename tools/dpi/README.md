# Обучение GBDT-гейта

Скрипт собирает окна из проверенных внешних UDP-кадров, сверяет целый uplink с nDPI и обучает маленькую модель. Модель повторяет решение "цель или туннель". Она не заменяет nDPI и не обещает устойчивость ко всем фильтрам провайдера.

## Каталог захватов

Путь передается в `--captures`. Значения по умолчанию нет.

Нужны три части и все 10 семейств в каждой: `train`, `val`, `test`. Это 30 независимых захватов. Удержание сессионное: семейство, включая WhatsApp SDES, входит и в обучение. Контроль не является удержанием маски и не является нетронутым финальным удержанием. Штатный генератор берет длины внутренней нагрузки из одного списка `8, 64, 256, 768, 1000, 4096` и меняет только зерно. Текущий провод держит начальный и минимальный MTU 1200, верх PMTUD 1380 и внутренний бюджет 1140.

Без `manifest.json` файлы лежат так:

```
captures/train/quic_https_v2.pcap
captures/train/quic_https_v2.verified.json
captures/val/...
captures/test/...
```

`verified.json` - JSON-массив hex-строк. Это отобранные внешние UDP-нагрузки после успешной транспортной AEAD, без рукопожатия и подтверждений. PCAP - классический RAW IP, DLT 101, весь клиентский uplink. Чтение поддерживает оба порядка байтов, микросекундные и наносекундные метки, расширения IPv6 и сборку IP-фрагментов. Направление определяется первым обменом: захват начинается с клиентского bootstrap, номер порта роли не задает. Порядок и кратность проверенных кадров сверяются внутри одного потока. Усеченные записи и незавершенная сборка отклоняются; одновременно допускаются 64 неполных IP-пакета со сроком 60 секунд. Пока нет всех тридцати пар, скрипт останавливается и не перезаписывает модель.

Необязательный `manifest.json` в корне каталога перечисляет те же 30 записей. Пути внутри него задаются относительно каталога:

```json
{
  "captures": [
    {
      "partition": "train",
      "mask_id": "quic_https_v2",
      "pcap": "train/quic_https_v2.pcap",
      "verified": "train/quic_https_v2.verified.json",
      "workload_seed": 11
    }
  ]
}
```

Поле `workload_seed` необязательно. Один и тот же файл двум частям не отдается. Все производные порчи остаются в части своего захвата.

## Метки и обучение

Положительное окно допустимо только если nDPI на целом PCAP, без угадывания по порту, видит QUIC или STUN с уверенностью DPI.

Отрицательное окно - порча реальных кадров: инверсия заголовка, шум той же длины, повтор с поломанным заголовком, отдельный шум. Вариант принимается только если nDPI сам называет поток Unknown или известным VPN. Если поток остался QUIC, STUN или другим узнаваемым не-VPN протоколом, он выбрасывается.

Гиперпараметры зафиксированы до контроля: 120 деревьев, глубина 3, скорость 0.15, seed 0, порог 0.5. Подбора по test нет. Основные метрики считают неперекрывающиеся окна, шаг 24. Шаг 8 считается отдельно и в обучение не входит. Порог узла при экспорте опускается до наибольшего f32, который не выше исходного double.

В обучение не добавляются синтетические векторы и повторы ради старых модульных окон.

## Что записывается

- `crates/aivpn-common/src/dpi_gate/model.rs` - таблица деревьев;
- `assets/dpi/windows.jsonl` - признаки, метки и части, без кадров и адресов;
- `assets/dpi/provenance.json` - хэши входов, вердикты nDPI, отброшенные порчи;
- `assets/dpi/metrics.json` и `assets/dpi/report.md` - метрики, константа большинства и ограничения;
- `assets/dpi/heldout_fixtures.json` - контрольные окна и вероятности для сверки с Rust;
- `assets/dpi/parity_fixtures.json` - эталонное окно признаков.

Полезные нагрузки и адреса в `assets/dpi` не кладутся. Сравнение с прежней таблицей включается только флагом `--old-model`. Путь к ней в публичные файлы не пишется, сохраняется только хэш, если флаг передан.

## Как запустить

Нужен отдельный интерпретатор. Системный Python эти пакеты не содержит.

```
python3 -m venv /tmp/aivpn-dpi-venv
/tmp/aivpn-dpi-venv/bin/pip install -r tools/dpi/requirements.txt
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 NUMEXPR_NUM_THREADS=1
/tmp/aivpn-dpi-venv/bin/python tools/dpi/train_gbdt.py \
  --repo . \
  --captures /path/to/captures \
  --ndpi target/dpi-tools/ndpi/example/ndpiReader
```

Проверки признаков, учителя, утечки и экспорта:

```
/tmp/aivpn-dpi-venv/bin/python -m unittest discover -s tools/dpi -p 'test_*.py'
```

Пул учителя ограничен двумя заданиями, потоки BLAS - одним. Версии пакетов закреплены в `requirements.txt`.

## Независимая проверка настоящего VPN

`evaluate_vpn.py` оценивает неизменную таблицу на отдельных PCAP известного VPN. Учитель должен подтвердить VPN, а проверенные кадры должны входить в PCAP в исходном порядке. Повторные захваты отклоняются. Хеш таблицы сверяется с источниками обучения, а хеши проверяемых захватов не должны встречаться ни в одной из частей обучающего корпуса. Окна не входят в обучение и не меняют порог.

```
/tmp/aivpn-dpi-venv/bin/python tools/dpi/evaluate_vpn.py \
  --captures /path/to/vpn-captures \
  --model crates/aivpn-common/src/dpi_gate/model.rs \
  --training-provenance assets/dpi/provenance.json \
  --ndpi target/dpi-tools/ndpi/example/ndpiReader \
  --output /tmp/vpn-evaluation.json
```

В каждой подпапке находятся `wireguard.pcap` и `wireguard.verified.json`. Текущая проверка использует три независимых соединения WireGuard с разными ключами, по 2048 подтвержденных UDP-обмена. Кадры DATA после рукопожатия отобраны с шагом 16; учитель nDPI определил WireGuard во всех трех захватах. Таблица распознала 15 из 15 неперекрывающихся окон. Признаки и хэши сохранены в `assets/dpi/external_vpn_fixtures.json`, кадры и ключи в репозиторий не входят.

Это проверка одного известного VPN и одного генератора нагрузки. Она не заменяет данные оригинальных приложений и не доказывает обнаружение неизвестных туннелей, которые nDPI по-прежнему считает QUIC или STUN.
