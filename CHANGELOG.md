# Changelog

## [1.2.0] - 2026-10-27

> **Dual-stack networking, signed distribution and application hardening.** This release extends IPv6 support across the tunnel, adds large management messages and new bootstrap/distribution channels, and fixes session, storage and platform security issues. Inter-server connections now use masked handshake sessions throughout; static legacy sessions and the server mode without a database are removed.

### Added

- **Android Material 3 interface** - separate VPN, profiles and settings screens, light and dark themes with optional system colors, compact session counters, responsive navigation and revised management forms. Profile changes remain locked during connection; theme, orientation and font changes preserve the active VPN session.
- **Current-wire DPI training** - authenticated external QUIC, RTC and STUN samples feed the classifier. Offline tools label complete captures with nDPI, keep independent sessions in separate partitions, and export a reproducible GBDT with Python/Rust parity checks and measured limitations.
- **Trained reference encoders** - offline Adam training uses separate training, validation and test windows. Versioned models load into the live detector only for matching mask signatures; invalid weights are rejected. Bundled held-out features check reconstruction without exporting packet contents. Current references cover the WebRTC and QUIC families.
- **IPv6 across the tunnel** - the server assigns an IPv6 address, prefix and MTU through `ServerHello`; desktop and mobile clients apply the assignment. Data, recovered FEC packets and forwarded traffic enforce source validation, client isolation and QoS for both address families. Server setup validates the prefix and configures forwarding and NAT66; an IPv6 setup failure stops startup.
- **Fragmented management messages** - requests and responses up to 512 KiB travel through the encrypted tunnel with separate nonces and sequence numbers per fragment. Reassembly is bounded to four incomplete messages per session and a ten-second timeout; conflicting fragments are rejected and partial messages never reach the handler.
- **Email bootstrap through JMAP** - clients can read signed descriptors from messages selected by sender and subject. The channel uses a configured HTTPS JMAP session endpoint and a read-access token.
- **Passive reception of signed masks** - DNS TXT, PNG RGB LSB, Bitcoin OP_RETURN and Ethereum calldata can carry signed mask profiles. Reception requires explicit network opt-in and a trusted operator key; size limits, signature checks and atomic profile installation apply before use.
- **Configurable DNS for SOCKS5 mode** - `--proxy-dns` accepts up to four IPv4 DNS servers, including internal resolvers reachable through the VPN. Regional hints also participate in mask selection without replacing a verified bootstrap descriptor with an unsigned preset.

### Fixed

- **Receiver feedback for uplink FEC** - fresh authenticated server RX reports select redundancy independently of RTT-based keepalive levels. Ordered reports expire after 30 seconds and reset with full PFS or reconnect; unknown feedback retains legacy adaptation. Complete receiver observations span inline key epochs and exclude rejected packets. Telemetry processing and replies are rate limited, and server peers do not echo reports.
- **Preferred masks after reconnect** - desktop and protected mobile retries choose matching candidates from verified bootstrap descriptors. If the requested base is absent, the client keeps the trusted opening and requests a server-signed mask after PFS. Confirmation checks the requested base and carrier; subsequent automatic rotations remain available.
- **Receive recovery after burst loss** - desktop and shared mobile decoding can resynchronize a large forward counter gap without reconnecting. The fast search and replay bitmap stay small; rare forward searches have a shared time and work budget, authenticate the packet before changing state, and keep separate quotas for current and previous keys.
- **Server configuration and administration** - persistent settings share the precedence explicit CLI > env > JSON > defaults, including nested fields and explicit false/zero values. Management errors carry stable codes and readable details; request scheduling and Android screen snapshots prevent stale replies and actions after refresh failures.
- **Backup destinations and standalone signing** - restore resolves the actual database and mask destinations before checking the live owner, preserves recovery of damaged configuration with explicit targets, and persists those destinations after archive verification. Signing a mask directory no longer requires access to an unrelated client database.
- **QUIC management messages** - established control messages use the existing full DATAGRAM budget, closing the gap between the old 512-byte bootstrap limit and the 900-byte fragmentation threshold. The initial cipher keeps its smaller limit.
- **Inline rekey under sustained traffic** - authenticated packets of the previous epoch advance a bounded counter-search hint without changing the new epoch replay bitmap. The hint survives transition expiry until a new-key packet is accepted or the session resets, preventing receive stalls behind a large old-key queue on desktop, Android and iOS. The server applies the same separation to its receive index, preventing repeated full-index rebuilds while old-key packets drain. Its bounded old-key tag band also follows authenticated traffic until the queue drains; replay records are pruned only after their tags leave that band.
- **QUIC throughput and local queues** - adaptive QUIC uses native congestion control and pacing without a second per-IP-packet timer. The client waits for DATAGRAM buffer space instead of discarding encrypted packets; pending control takes priority over data. Established, admitted PFS sessions have a separate finite packet-rate budget, preserving the pre-authentication limit. The receive decoder remembers an authenticated header layout, and server startup no longer forces packet-level debug logging.
- **Linux low-MTU IPv6 protection and recovery** - full tunnels without an assigned IPv6 address use owned blackhole routes even below MTU 1280. IPv6 assignment enforces the protocol minimum. Route changes use exact privileged-helper operations, preserve foreign routes and continue cleanup after a missing route. Explicit `kill-switch clear` also removes owned IPv6 guards left after a crash; ordinary startup does not remove leftover IPv6 guards.
- **Adaptive data pacing** - outside native QUIC pacing, client uploads and server downlinks shorten profile intervals gradually when scheduler queue delay persists, avoiding full-tunnel stalls caused by a fixed per-session packet rate. The original cadence returns as the backlog clears. Acceleration is bounded and does not accumulate a catch-up credit. Local `upload_shaping` and `downlink_shaping` settings select `adaptive`, `full` or `off`; omitted settings default to `adaptive`. Existing server `true` and `full` settings remain strict and require an explicit change to enable adaptation. Android and iOS forward the active profile interval through the shared uploader. Adaptive mode preserves padding and encryption, but changes timing under load; this does not establish resistance to DPI.
- **Responsive paced traffic** - bounded per-flow queues in both directions keep DNS and new connections from waiting behind a bulk transfer while preserving packet order within each flow. Strict `full` mode retains the profile intervals. Linux full-tunnel teardown preserves the original default route and its metric instead of adding a duplicate.
- **Android profiles and system windows** - refresh imported profiles before saving the main screen, keep a granted VPN request across Activity recreation and asynchronous key loading, and retain the installation wizard during night mode changes. Empty client names keep the administration form open; a failed exit assignment reports that the client was already created.
- **Android storage compatibility** - classify Keystore failures without linking to an exception type published in API 33, keeping recovery usable on older supported Android versions without deleting profiles after transient errors.
- **Bounded server workloads** - limit pending DNS queries, unauthenticated source tracking and webhook queues. Slow upstream services no longer allow unbounded background work or source tables; webhook HTTP errors are reported without logging credential-bearing URLs.
- **Private local state** - bootstrap, mask feedback and desktop settings use exclusive random temporary files. Cache reads reject symlinks, FIFOs and oversized files; bootstrap updates validate ownership and serialize writers. Verified network descriptors remain available in a bounded memory cache when disk writes fail. Cache locks are explicitly released even if a concurrent child process inherited their file descriptor.
- **Linux desktop status updates** - an unavailable notification service no longer blocks the UI before it displays a confirmed connection. Notifications run in one background worker with a bounded queue that retains the latest state. The connection button keeps its width as traffic counters grow. User-scoped status files keep counters and the timer working when old root-owned files remain.
- **Linux network permissions** - the installer no longer grants network administration to the system `ip` command and removes the previous grant while preserving other capabilities. Verified network and firewall commands inherit the client's existing privilege, including kill switch setup; the polkit helper also handles tunnel MTU setup.
- **Web authentication and upgrades** - existing databases receive the missing user session version. Concurrent password checks count toward brute-force limits, passkey counters cannot move backwards, and a full rate-limit table evicts old entries without scanning every key.
- **Desktop profiles and network changes** - Windows preserves the selected profile when an unreadable key is removed and uses the correct ProgramData fallback. Desktop import rejects profiles without a server address; Linux also accepts whitespace around a pasted key. iOS keeps a working tunnel when only a standby interface changes. OpenWrt displays the real service state, reports failed actions and preserves the router kill switch across WAN recovery.
- **Audit chain integrity** - independent writers share a locked chain tip without loading the entire log. New hashes encode field lengths to detect edits that move separators between fields; existing hash versions remain verifiable. An interrupted final write is recovered before appending the next entry.
- **Android network recovery** - reconnect automatically after loss or replacement of the underlying network, including networks where Android cannot validate public internet access. Preserve the request to keep VPN active while offline, update connection status immediately, and stop the old mobile tunnel without waiting on a closed socket. Empty UDP datagrams no longer monopolize the mask worker.
- **Reconnect after cancelling a handshake** - a fresh authenticated attempt can replace an unfinished attempt for the same client. The established session remains active until its replacement is admitted; session limits and initial-handshake replay protection remain enforced.
- **Android connection lifecycle** - apply the authenticated server network assignment before announcing a working tunnel, without a second handshake. Ignore stale callbacks, revocations and cleanup from replaced services, keep duplicate connect requests idempotent after server configuration changes, lock profile editing while a connection is starting, and translate the live connection status after a language change. Instrumented tests cover repeated connections, settings, traffic and Activity recreation.
- **Connection startup and reply addresses** - Android resolves the VPN server through the physical network before sending direct UDP traffic. Desktop clients resolve and open the transport before creating TUN routes, avoiding DNS overlap with the VPN subnet. Linux servers preserve the destination address of authenticated UDP packets when replying, including QUIC and RTC carriers on hosts with several IP addresses.
- **Bootstrap cache after catalog upgrades** - the server restores the known profile requested in the authenticated initial exchange when a cached descriptor selects a different base from the expanded catalog. A matching STUN header no longer completes PFS with the wrong RTC profile and leaves the tunnel unable to carry data.
- **Client configuration validation** - malformed local JSON and transport parameters now stop startup before network changes. Global runtime settings remain separate from connection profiles and survive reconnects.
- **DNS address failover** - desktop and mobile direct UDP connections try other resolved addresses after unsuccessful attempts and prefer the last address confirmed by a PFS handshake. One unreachable A or AAAA record no longer traps reconnects on the same endpoint.
- **Signed reverse profiles** - signing a mask signs nested reverse profiles first, so strict verification accepts each profile both inside its parent and when sent separately. Server security features also propagate to the embedded client and shared core.
- **Handshake and keepalive validation** - an invalid initial ServerHello is rejected; an invalid repeat after verified PFS cannot disconnect the established session or change its keys and network settings. Desktop and mobile keepalives stay below the QUIC idle timeout, and repeated Hello messages retain the latest adaptive level. Protected builds propagate descriptor enforcement and cycle through trusted descriptor epochs and slots after failed attempts without permanently excluding recovered candidates. Cached descriptors are rechecked against the current server key, and an empty cache retries configured URLs. Repeated short data stalls advance to another trusted candidate.
- **Small QUIC paths and gateway ping** - QUIC starts at 1200 UDP bytes, probes the path MTU within the mask budget and fragments inner traffic to fit the initial path. Gateway echo replies include valid IPv4 and ICMP checksums and handle IPv4 options safely.
- **RTC startup and packet limits** - queued tunnel data waits for the outer channel, SRTP and TURN overhead stay within the wire MTU, and a full actor pool releases the old generation before retrying an authenticated mask change. A changed signed RTC profile creates fresh negotiation parameters even when its id and version stay unchanged; retired offers cannot replace the new channel. Derived TURN profiles keep their base realm. The PCAP gate validates TURN and SDES framing.
- **Reference model activation** - the gateway loads weights before registering masks, reports library errors, and replaces stale encoders when a signature changes. Invalid dimensions, zero check intervals and non-finite thresholds are rejected. Held-out checks also compare learned models with the training-set mean predictor.
- **Mobile domain exclusions** - IPv4 and IPv6 exclusions work on supported Android versions, including versions before Android 13, and on iOS. Routes refresh on connection and iOS DNS resolution has a deadline. Apple clients reject interface-scoped IPv6 and embedded NULs in routes, negotiated addresses and server endpoints.
- **Session diagnostics and desktop management** - latency, probe loss, upload and download speed are measured over the active encrypted VPN session using acknowledged test data. A direction without confirmed test blocks reports an error. Desktop management discards replies from previous sessions and pins each command to its original credentials. Large local management replies use bounded TCP frames instead of a single UDP datagram. macOS routes privileged-client management through its authenticated helper; failed exit-node assignment is reported without creating the client twice.
- **Server telemetry** - quality reports from current clients feed anomaly detection with normalized loss values. Old reporters expire with the measurement window, traffic-rate features update from packet samples, and telemetry responses use session metrics and actual queue occupancy. Packet loss follows the authenticated receive window, including kernel-offloaded traffic; late arrivals repair gaps without counting acknowledgements twice.
- **Credential storage and IPv6 keys** - macOS updates Keychain entries without deleting the previous value and stores the profile list atomically; failed writes remain visible. Windows refuses to save a bootstrap token if encryption fails and migrates existing plaintext tokens correctly. Connection keys preserve bracketed IPv6 addresses on the server and in the iOS tunnel.
- **Tunnel packet sizes and mask transitions** - the default TUN MTU is 1280 and explicit values up to 1500 are preserved. Large DATA and FEC repairs are fragmented to fit the carrier budget; each original IP packet enters FEC once, and a group survives mask changes. Adaptive FEC settings update the active uploader at group boundaries. Authenticated group and position metadata prevent mixed-group recovery; late originals are rejected before reassembly and FEC always uses userspace reception. Expired or evicted groups retain member history and cannot recover already delivered packets. Mobile sessions apply a pending mask even while sending only keepalives; encrypted control fields reject lengths that cannot fit their wire encoding. Invalid non-finite mask parameters are rejected before signing.
- **Web sessions and SSO** - access tokens and SSE tickets are checked against live sessions; revocation also closes active streams. Session generations prevent stale refresh writes, TOTP races and concurrent passkey deletion from restoring access or removing the last login method. SSO validates required claims and PKCE cookies, handles concurrent account creation, and bounds discovery and token requests. Browser caches and pending refreshes are cleared across account changes.
- **Streaming management proxy and configuration rollback** - uploads respect backpressure and size limits; response bodies stream with cancellation and deadlines. Configuration writes remain private and atomic, expired confirmations are rejected, failed rollbacks are retried, and temporary backup files are removed on errors.
- **Platform clients and routers** - desktop profile selection persists, Linux and iOS preserve handshake refusal reasons, and iOS waits for on-demand changes before stopping the tunnel and isolates persistent credentials by profile. Windows decodes grayscale QR images safely and offers diagnostics to ordinary connected clients. OpenWrt restarts failed clients without a retry ceiling and requires a PSK in manual mode. OpenWrt and MikroTik preserve WAN access by default and provide an explicit blocking option.
- **Protected network operations** - service DNS and sockets use platform routing protection, Linux helpers accept IPv6 routing operations, and missing kernel QoS state falls back to userspace without consuming the replay counter. Linux privilege setup transfers installation bytes through a pipe into a root-owned directory and verifies installed files and capabilities.
- **Unverified Alice mask** - `yandex_alice_v1` is temporarily excluded from the bundled catalog, CLI selection and installation bundle. The observed mobile Alice voice RPC uses TLS/TCP and does not match the current UDP profile. The smart speaker has not been verified separately.
- **Zoom and Telemost RTC masks** - after PFS, the common mask layer negotiates ICE credentials, the DTLS fingerprint and SSRC through a bounded `MaskState` message. Data uses ICE/DTLS/SRTP over the existing UDP socket. Repeated offers are idempotent, unknown SSRCs are rejected before state allocation, and padding and MTU account for 28 bytes of SRTP overhead. Queues and handshake time are bounded; this does not establish full application indistinguishability.
- **TURN and standalone SRTP modes** - SberJazz and Telegram call masks perform authenticated Allocate, Permission, ChannelBind and Refresh before carrying ICE/DTLS/SRTP inside ChannelData. WhatsApp uses ICE/SRTP without DTLS, with separate directional secrets negotiated only after PFS. The server does not open relay sockets to external addresses supplied in TURN messages. Queues, replay caches, SSRC counts and setup time are bounded.
- **HTTP/3 negotiation in QUIC masks** - SETTINGS, control and QPACK streams, CONNECT-UDP with a 200 response, and HTTP DATAGRAM contexts are negotiated before data starts. Readiness requires the application protocol, not only TLS. This fixes internal h3 consistency without claiming that CONNECT-UDP matches ordinary requests to a particular website.
- **Mask scheduling and generations** - deferred downlink retains FSM padding overrides and checks both forward and reverse profile generations before transmission. Closing an old queue no longer removes its replacement session. Unnecessary NACK without RTX is disabled to avoid frequent idle RTC wakeups.
- **Telegram mask target** - `telegram_calls_v1` replaces the incorrect QUIC-based `telegram_mtproto_v1` profile for UDP calls. The old ID is removed and explicit mask selections must be updated. The mask follows observed TURN/ICE/DTLS/SRTP stages without implementing the call control protocol.
- **Packet-size models and intervals** - unsupported `Bimodal` models in Zoom, Telemost and `webrtc_sberjazz_v1` profiles are replaced with models from real captures. Forward and reverse directions have separate distributions; Telegram calls also use a captured UDP flow. These are marginal models of specific captures, not acceptance of statistical application indistinguishability. A self-transition without overrides resets stale parameters and packet counters on client and server.
- **Initial exchange under packet loss** - desktop and mobile cores retry InitialV2 on a separate jittered timer bounded to ten seconds. Attempts retain their key and use a fresh nonce for each retry. The gateway limits ServerHello retries; data and control still require PFS.
- **Mask framing and state** - seven profiles with STUN bootstrap use aligned TLVs and correct lengths in both directions. Three QUIC profiles maintain bidirectional QUIC v1/TLS 1.3, acknowledgements, loss handling, timers and DATAGRAM over the existing UDP socket instead of creating a decoy Initial for each packet. The pre-validation amplification limit is 3x. A malformed outer Initial does not consume an inner handshake replay nonce.
- **Profile-based data pacing** - the client applies IAT during continuous uploads without delaying control messages or RTT probes. The server queues raw IP packets per session before QoS and encryption, with bounded queues and no catch-up burst after a pause. Downlink uses the reverse profile when available. FSM parameters also apply on transitions to the same state.
- **STUN profile sizes** - bundled profiles and the generator use the selected size instead of adding random 0-64 byte padding. Seven bundled STUN profiles no longer share a joint model and FSM that override their individual distributions. Padding does not shrink the original packet or reproduce an application's ICE, DTLS or SRTP by itself.
- **Profile selection and switching** - all ten bundled masks are selectable and unknown IDs are rejected. The verified profile is negotiated before the first ServerHello. STUN/QUIC transitions and polymorphic QUIC updates preserve the session; large MaskUpdate messages are fragmented before encryption. Bounded queue overload drops a packet instead of the entire tunnel.
- **Mask changes after idle periods** - the server accepts current and pending layouts until the transition finishes. A valid packet after the grace period commits the mask and updates the kernel layout without requiring downlink; corrupted ciphertext and replay do not change state.
- **SOCKS5 TCP half-close** - a remote FIN forwards EOF locally while leaving the client's upload open. Late data reaches the server, buffered replies finish, and cancellation or local EOF stops tasks within a bounded wait.
- **Pool exit reconnects** - a retired dialer cannot overwrite the sender or status of a new connection during rapid removal and re-addition. Publication checks its original generation token under the topology lock instead of waiting for stop-watcher polling.
- **Handshake lookup budgets** - the server tag index covers adjacent time windows without a broad scan for every packet. Pre-authentication work has an elapsed-time budget while legitimate reconnects remain possible. Forced verbose logging is disabled.
- **Replay and device identity** - replay validation and marking are atomic after AEAD in the correct epoch, and replay history survives key rotation. Management roles require proof of the persistent device key; mTLS checks that key and certificate expiry regardless of enrollment order.
- **Offline backup restoration** - restoration is restricted to the CLI after stopping the server and every process using the database. HTTP and web interfaces only validate archives. Locking prevents a running process from overwriting restored data with stale memory. Import bounds decompression and rejects path traversal; export rejects symlinks and creates private files.
- **Authenticated session admission** - a new session must complete PFS, prove a bound or privileged device key and satisfy required mTLS before claiming a VPN address. An unverified session cannot displace a live tunnel. Lost proofs and certificates are retried after the same Hello; incomplete authentication expires after 60 seconds. Role announcements follow authentication and permission changes. Management operations preserve pending configuration transactions, client creation is atomic, and reset device bindings do not retain inherited privileges.
- **Platform lifecycle and web challenges** - DNS and route protection, optional Android keys, client connection state, SOCKS task cleanup and session shutdown are corrected. Web authentication bounds pending challenges and prevents bypassing required OIDC through passkeys or direct event streams.
- **Kernel path and packaging** - fixes cover epoch and resource-release races, unknown-address isolation, XDP pass-through, checksums, TC token accounting, removal of the application's own TC filter and packaging errors. Actual kernel support still depends on compatible Rust-for-Linux APIs and toolchains.
- **CI classifier download** - keep nDPI outside the Cargo cache and explicitly select its Git directory so incomplete cached metadata cannot redirect fetches to the application repository. Fetch the release tag with bounded retries and verify the pinned commit before building.
- **Multiple client instances** - a busy admin socket no longer causes a CPU spin or overwrites another client's token. `--admin-listen` / `AIVPN_ADMIN_LISTEN` selects a separate loopback endpoint for each instance and its management commands; recording status, traffic and quality files are isolated. Pending management replies release the socket when the session ends.
- **Reconnects behind NAT** - a PSK-verified client can replace its existing session at the per-IP or subnet limit without disconnecting neighboring clients. Replacement slots are bounded, duplicate pending replacements are rejected and new clients retain the normal limits.
- **macOS application location** - the GUI and privileged helper share the permitted binary paths. A renamed or relocated app uses the installed system client instead of passing a path that the helper rejects.
- **MikroTik build instructions** - corrected repository paths and the runtime architecture in the arm64 Docker example; documented local image export and RouterOS file import without relying on a missing registry image.
- **Concurrent database and status writes** - `clients.json` mutations lock and reload the current file before saving, preventing one process from overwriting another's changes. Failed saves no longer leave a successful change only in memory; client status snapshots are written atomically.
- **IPv6 assignment and packet handling** - desktop routes follow the assigned network and are removed on disconnect; Android rebuilds the tunnel when the address, prefix or MTU changes, and iOS applies the assignment through Network Extension. DSCP updates preserve ECN, and IPv4 checksum calculation includes header options.
- **Management request deadlines** - the timeout now covers waiting for queue capacity as well as the response, so a full transport queue cannot leave a request waiting indefinitely.
- **Linux kernel session lifecycle and accounting** - session removal also removes kernel state; accelerated traffic contributes to activity and statistics, including small increments and counters carried across a ratchet. Losing an established shared replay window requires a new handshake instead of silently resetting replay history.
- **Web panel authentication and database compatibility** - fixed concurrent refresh-cookie updates, PostgreSQL schema types, strict interface typing, accessible button names and reproducible Docker builds.
- **Apple identity and helper error handling** - Keychain and random-number generation failures are propagated, malformed stored keys are rejected, and the macOS helper reads certificates with file-safety checks.

### Security

- **TUN descriptor ownership** - updated Tokio to 1.53.3. Mobile TUN I/O owns its registered descriptor, synchronizes nonblocking polling with shutdown, and deregisters before closing. Stop no longer replaces a live registered descriptor with another file; cancellation closes the TUN without waiting for runtime progress.
- **QUIC ML features and training balance** - spin and protected short-header bits are normalized only in classifier features. Training balances classes, masks and original sessions; utility uses balanced accuracy and reports family-level errors separately. The runtime decision threshold is unchanged.
- **QUIC bootstrap and admission** - a cold Initial has an empty Token; the inner AIVPN bootstrap travels only after TLS and HTTP/3 CONNECT-UDP inside encrypted DATAGRAM. Pending transports have bounded counts, lifetime, queues and CPU work. Forged, replayed or retired generations cannot replace an active VPN session or consume its replay state. Valid client MAX_PUSH_ID control frames are accepted. Normal HTTP/3 probes receive a bounded denial response without opening an external UDP proxy.
- **DNS and constant-time cryptography** - upgraded Hickory to 0.26.3, `crypto-bigint` to 0.7.10 and `ctutils` to 0.4.6. WebRTC uses the AWS-LC backend to remove the affected `crypto-bigint` 0.5 dependency. DNS response validation and socket protection remain enforced; no audit exceptions are added.
- **TLS certificate validation** - `rustls-webpki` is updated to 0.103.16 and `webpki-roots` to 1.0.10, addressing RUSTSEC-2026-0382 and RUSTSEC-2026-0381. Chains containing revoked emSign intermediates are rejected and the affected root is removed from the trust set. CI still requires `cargo-audit`, with no new exceptions for these advisories.
- **Inter-server permissions and live revocation** - site peers can exchange routes and site traffic without receiving pool database or management rights. SiteData sources are checked against the authenticated node's subnets; strict enrollment binds identity to the handshake. A shared site key supports an identity allowlist but must differ from the pool key. Revocation is checked on active connections, and an old session cannot inherit the rights of a node registered again under a new key.
- **Persistent identities and trust registry** - device and node keys are installed atomically without overwriting another process's key. Corrupt keys are not silently regenerated. Node trust is granted only after persistence succeeds; registry corruption, disappearance or symlink substitution denies access.
- **Enforced signatures in `production-secure`** - secure builds require trusted signing keys and artifact verification. The mask generator signs both forward and reverse profiles, and Ed25519 verification rejects small-order public keys.
- **Signed release artifacts** - CI signs server binaries and mask archives with Ed25519 and checks that the configured signing keys match. The SSH installer verifies downloaded artifacts against a separately trusted public key; HTTPS downloads enforce size and redirect-address limits.
- **Persistent Windows kill-switch** - dedicated Windows Filtering Platform filters are updated in one transaction and survive a client crash. Explicit disconnect removes the filters and reports cleanup failures; unrelated firewall policies are preserved.
- **Dependency fixes** - updated affected Rust and web dependencies, including `quinn-proto` 0.11.18, `rustls` 0.23.46, `rustls-webpki` 0.103.16, `webpki-roots` 1.0.10 and the vendored `cryoglyph` dependency on `lru`. A local `braces` patch caps parser nesting at 128 levels and has regression coverage; version-based audit tools still report the unchanged `3.0.3` package version.

### Changed

- The QUIC mask format and bundled STUN profile versions are incompatible with earlier 1.2.0 development builds. Servers, pool/site/chain nodes and all client cores must be updated together. No new TransportKind is added; the native systemd deployment and connection-key format remain unchanged. QUIC runs in userspace in both directions, as does STUN downlink; the kernel ABI is unchanged by this mask-format update. Previously signed external STUN profiles must be reissued instead of changing signatures on clients.
- The initial exchange uses a separate KDF v2 and XChaCha20-Poly1305 with a random 24-byte nonce. AEAD binds the tag, counter, direction and connection context. Retrying initialization after a restart or on another node does not repeat a server key/nonce pair. Established channels and the kernel ABI retain their existing format.
- Initial handshake compatibility with released 1.1.0 and earlier 1.2.0 development builds is broken. Update servers, pool/site/chain nodes and every client build, including embedded mobile cores, together. There is no automatic fallback to the old exchange. Connection keys, PSKs, static server keys and the native systemd deployment format are unchanged by this handshake update.
- The initial epoch only establishes the connection; data and management commands require confirmed PFS. Every new client connection gets a fresh ephemeral key, and a delayed ServerHello from another connection cannot replace agreed keys or network settings.
- **Linux kernel ABI 7** - client and server share replay-counter claims, key epochs, access policies and per-client QoS with the kernel path. FEC, DSCP processing, metadata recording, neural checks and shaped downlink retain the userspace processing they require. Server IPv6 downlink remains in userspace; kernel server downlink is explicitly enabled with `AIVPN_KERNEL_DOWNLINK=1`.
- **Blocking correctness checks in CI** - Clippy `correctness` and `suspicious` diagnostics fail the build while style warnings remain visible. The DPI gate requires a pinned nDPI toolchain instead of skipping classification when the tool is absent. Tests and Clippy explicitly enable server and client ML-DPI features.
- **Upgrade requirements** - update inter-server nodes together, remove explicit `pool.transport=legacy`, configure the client database and rotate previously used static keys. Distribute trusted release/operator public keys before enabling signature enforcement. Configuration details are in [release settings](docs/RELEASE_1.2.0.md).

### Removed

- **Static legacy sessions and the standalone chain forwarder** - pool, site and exit connections use masked handshakes with individual session keys, rotation and replay protection. An omitted `pool.transport` selects `masked`; an explicit `legacy` value is rejected. Ordinary PSK handshakes and the tag-prefix packet layout used by handshake sessions remain supported.
- **Server operation without a database** - the fixed fallback address pool is removed; address allocation uses the client database's network configuration and pool partitions.

### Refactored

- **Code cleanup** - removed dead functions and obsolete branches, separated shared settings and constants from local variables, and kept local variables in the smallest useful scope.

### Testing

- **Live mask gate** - CI runs the client and gateway over UDP for all 10 profiles instead of using a one-way synthetic PCAP. Scenarios include lost Initial/Hello messages, 100/500 ms RTT and duplicates, plus STUN/QUIC transitions and corrupted outer Initials. TShark validates framing; nDPI checks the full flow and its first packet. Classification does not establish full application indistinguishability or resistance to every DPI system.
- **Regression coverage** - authenticated session diagnostics, delayed management replies across reconnects, web session revocation and SSO races, native profile persistence, router restart and blocking policies, kernel policy fallback and build packaging have automated regression checks.

## [1.1.0] - 2026-08-20

> **First minor release since 1.0.x.** It consolidates everything after the RC2 label (2026-07-18) on top of the 1.0.2–1.0.5 fixes: a redesigned pool-sync transport, a behaviour-preserving architectural refactor of the largest modules, unification of the two mobile tunnels onto one shared core, and a seam for pluggable datagram transports. The version moves to 1.1.0 because the mobile cores, the GUI hosts and the client entry point changed shape — the wire protocol did not.

> **Release candidate for 1.0.0 (label RC2).** No version bump — the apps still display **1.0.0**; “RC2” is only the release label. This entry consolidates everything since RC1 (2026-07-07): a large reconnection-stability and pool-IP-coordination pass, a full security-hardening audit round across every platform, protocol correctness fixes, and a handful of new capabilities (authenticated handshake-reject, configurable downlink shaping, a native OS network-change listener, and honest min-cluster mask fitting).

### Added

- **In-app client administration (Phase A)** — a new `ClientRole` (`User` / `Viewer` / `Admin`) with device-binding, plus `Capabilities`/`MgmtRequest`/`MgmtResponse` protocol control messages, let an authenticated admin manage the client roster *through the tunnel itself* as well as over REST. Full client CRUD (list/add/edit/QR/revoke) is now available, role-gated, from every client UI — Linux, Windows, macOS, iOS, Android — and the web panel. `Admin` revoke force-disconnects the target session immediately and blocks reconnection. Every mutating admin action lands in a tamper-evident hash-chain audit log, with a verify badge in the web panel. Heavy settings changes (active mask, exit node) apply through commit-confirmed rollback: an unconfirmed pending change reverts automatically.
- **Pool topology and per-client exit routing (Phase B)** — the server exposes pool topology (nodes/health/links) over a curated management path; the web panel renders it as a live graph. Nodes exchange `PartitionAnnounce` info and enforce hard per-node VPN-IP partitions with deterministic re-homing, eliminating pool-add IP collisions. Each client can be pinned to a specific exit node, with a pool-wide default exit; the change takes effect live through a runtime dial-add-peer path — no server restart needed. Pool topology and exit-node controls ship on all five client UIs and the web panel.
- **SSH server installer (Phase C)** — a new idempotent, systemd-first installer script (`deploy/install-server.sh`, managed via `##AIVPN` markers) stands up or upgrades an `aivpn-server` over plain SSH, including firewall rules. A `russh`-based SSH-install client (TOFU host-key pinning, sftp upload, `##AIVPN`-marker progress streaming) lives in `aivpn-common` with an embedded installer bundle, shared by the desktop CLI (`aivpn-client ssh-install script|probe|run`) and a mobile FFI/JNI surface (probe/start/poll/free with an event queue). All five clients gained an in-app "install a server via SSH" wizard, reachable without an existing connection so it can bootstrap the very first server from scratch, with TOFU confirmation, script/SHA-256 review, live progress, and `aivpn://` connection-key import on success. Server migration remains a web-panel-only feature and was deliberately left out of every native client. The server gained a `--device-pubkey` flag to create a device-bound (admin-capable) client at add time, and the mobile cores gained a device-pubkey getter so the wizard's "bind to this device" toggle works end to end. CI now publishes full-feature x86_64 + aarch64 server release binaries with SHA256SUMS.
- **Full native parity for in-app administration** — every native client (Linux, Windows, macOS, iOS, Android) now ships the complete admin surface, not just client CRUD: a **read-only `Viewer` mode** (the whole admin panel opens for a `Viewer` with all mutating controls hidden, matching the server's Viewer-GET allowlist), a **hash-chain audit-log viewer** with a chain verified/BROKEN badge (previously web-only), a **"Server Settings" apply-with-rollback panel** (change the active mask or the pool-wide default exit through the same `config/apply` → confirm-within-~120s-or-auto-revert flow the web panel uses), a **pool-node exit-node picker** (dropdown of discovered pool nodes with a live-vs-restart hint instead of a raw `host:port` field), and **automatic `aivpn://` key import** after a successful SSH install. The mask list (`GET /api/v1/masks`) is now reachable over the curated management tunnel (Viewer+Admin, read-only) so the native mask pickers share the web panel's data source.
- **Authenticated `HandshakeReject` — the server now tells a PSK-proven client *why* it was refused** — when a peer completes the authenticated handshake but is rejected (one-time key already used, key expired, or client disabled), the server returns an AEAD-encrypted reject reason instead of silence, and the client surfaces it and stops the reconnect loop instead of hammering forever. Unauthenticated probers still get pure silence (unobservability is preserved). Implemented across the server, iOS, Android, and desktop clients.
- **Configurable downlink traffic-shaping level (`off` / `light` / `full`)** — the server→client shaping introduced in RC1 is now a three-tier `ShapingLevel` knob (`downlink_shaping` in `server.json`, selectable in the web panel) instead of an all-or-nothing switch, trading covertness against downlink throughput per deployment. Backed by MDH-pool pre-generation on the server hot path.
- **Native OS network-change listener for the desktop client** — Linux (a `NETLINK_ROUTE` multicast listener on the LINK + IPv4/IPv6 IFADDR groups) and Windows (`NotifyIpInterfaceChange`) now push an interface/address-change signal into the reconnect path, so a Wi-Fi switch or cable event triggers a reconnect in milliseconds instead of waiting out the 5–10 s poll-based watchdogs. Best-effort and non-fatal; it only acts once the tunnel is established (see the matching fix below).
- **Bootstrap-fallback status line** — the desktop client emits an explicit status when it falls back to the built-in default mask after repeated unmatchable handshakes, so operators can see the covert-descriptor path degrade instead of guessing.
- **Android hardware-backed key storage (StrongBox)** — the Android client now stores its device key in StrongBox-backed Keystore where available, with a graceful fallback, hardening key material against extraction.
- **Honest min-cluster mask fitting (R6a) in the server generator** — `mask_gen` now selects the Gaussian-mixture component count with a min-cluster-weight floor enforced *during* BIC selection (reject any `k` whose smallest component carries <5 % of the mass), instead of over-fitting a high `k` and pruning the spurious micro-modes afterward. Verified DPI-detection-neutral through the offline nDPI eval-gate. Cleaner, honest per-protocol size/IAT distributions with equal-or-better fit to real traffic.
- **Server CLI parity for client mutation + management-API backup dry-run** — every client field editable over the management API is now also editable from the server CLI, and `backup/import` gained a dry-run mode.
- **`management_socket` configurable from `server.json`** — the management-API Unix socket path (and `pool.node_id`) can be set in the config file and is documented in the example, instead of being CLI-only.
- **Server socket-group knob** — the management/API socket can be created `0660` owned by a configurable group, so the web panel can run non-root against it without world-writable exposure.

### Fixed

- **Reconnect storms across every client — the biggest theme of this release.** Broke an infinite reconnect loop on an unmatchable cached bootstrap descriptor (mobile); ended the auto-mask "hopping" loop with a sticky mask that is abandoned only after repeated short data stalls; added proactive reconnect on carrier change for iOS/Windows/Linux; fixed Android reconnect ping-pong every 5–10 s on multi-network devices, an `onLost` restart when a *secondary* network dropped, and a connect-time UI race; fixed the iOS in-extension reconnect loop, network-change restart, and wake probe; and stopped macOS reconnecting on secondary-interface churn rather than real path changes.
- **Native network-change listener no longer self-triggers an unbreakable reconnect loop** — the new Linux listener subscribes to the same IFADDR/LINK groups the client's own TUN bring-up emits on every connect, so it tore the session down microseconds after the init handshake (before the server reply) and re-armed on each retry — the tunnel never established in full-tunnel mode. The listener is now honored only once the tunnel is established; pre-establishment self-inflicted churn is drained and ignored. A genuine change in that window is still covered by the handshake-fallback path and the poll-based carrier-change watchdog.
- **Pool-wide VPN-IP coordination and re-home healing** — the server now re-homes IP-conflicting clients during pool sync instead of dropping them, self-heals a lost `vpn_ip_map` entry that silently blackholed downlink, resolves hostname pool peers instead of failing to push, and sweeps orphaned `pool_sync` counter temp files on startup. Clients (desktop/Windows/Linux, iOS, Android) now adopt the server-assigned VPN IP after a pool re-home and rebuild the tunnel, ending the "connected but no traffic" anti-spoof-drop state; a stale TUN address is dropped when the server re-homes the client.
- **Length-aware embedded-tag mask framing on both wire ends** — corrected the on-wire framing for masks that carry the resonance tag at an embedded offset (WebRTC/QUIC layouts), fixing a data-plane mismatch between the client and server ends.
- **`DeviceEnrollment` proof bound to the session transcript** — the enrollment proof is now bound to the specific session transcript (and the server keeps the server ephemeral public key across the ratchet for it), closing a replay/confusion gap in just-in-time device enrollment.
- **Live quality score** — Android now reads the live quality score instead of a stale cache and resets it at session start; RTT keeps being measured under continuous load (it previously stuck at 0), and a clock-skew sample no longer drops the score to zero.
- **Session timers and post-freeze liveness across desktop/iOS/Android** — the connected-since timer is now owned by the service/core (not the UI), so it survives silent reconnects, and a post-wake/post-freeze liveness probe condemns a dead session promptly after suspend instead of lingering.
- **Empty `clients.json` treated as an empty database, not corruption** — a fresh/empty client database no longer aborts server startup.
- **macOS "Service unavailable" with a healthy helper** — hardened the helper IPC (PID-reuse safety, fail-closed peer check, symlink-safe status read, socket-ownership tracking), added a UI retry path, moved recording through the helper, and fixed a helper allowlist that rejected the bundled client on bundle-ID capitalization.
- **Linux and Windows GUI robustness** — Linux GUI: orphan-client recovery, cleanup-safe teardown, real status and live stats; Windows GUI: startup-connect hop, hidden-window supervision, kill-switch recovery, and a stale VPN IP shown after a pool re-home; a Linux connection timer was added.
- **Kernel module correctness** — corrected the ioctl direction bits, moved decrypt off the session lock, and fixed a stack/lifetime issue in the in-kernel data path.
- **Deploy/build repairs** — restored the musl/embedded and Windows release builds, fixed `make` targets and Docker build contexts, repaired OpenWrt/MikroTik packaging and the CI gate, and installed `nftables` in the runtime image.
- **Pending-config double-apply could roll back an already-confirmed change** — the server's apply-with-rollback path is fixed so a second pending change no longer reverts a setting the admin already confirmed; REST-set `exit_node` was cached but not pushed to the live routing table — it's now applied immediately.
- **Web panel pool-topology reads 403'd for `Viewer`** — the pool nodes/health/links GET routes are now allowlisted for the read-only `Viewer` role instead of requiring `Admin`.
- **Desktop client mislabeled a post-connect `ssh-install` failure as a connection error** — the CLI/UI now attribute the failure to the install step, not the tunnel.
- **Windows SSH-install wizard channel reuse** — the wizard reused a single mpsc channel for the app's whole lifetime, so closing it mid-install and starting a new run interleaved both runs' output lines; the channel is now recreated per install run.
- **Android install wizard lost unsaved input / left cache litter** — Step-1 fields are now synced before backgrounding into the SAF file picker (previously discarded on return), and cached binary copies get best-effort cleanup.
- **Linux: missing Russian translation for the install wizard's "Install" button**, found during review.

- **The rekey grace window never actually worked** — at a PFS ratchet or an inline rekey the server kept the outgoing epoch's resonance tags but overwrote the keys they were minted under, so an in-flight old-key packet resolved its tag, passed anti-replay, and was then decrypted with the freshly installed *current* key: AEAD failed and it was dropped anyway. The mechanism written to stop packet loss at a key seam prevented none of it, worst on exactly the high-RTT links its window scales for. The outgoing keys are now retained for the same window and tried after the current key fails, so current-epoch traffic keeps its single-attempt fast path.
- **macOS shipped a privileged helper that rejected the app** — the build script signed the app ad-hoc and never signed the helper at all, while the helper (correctly) pins socket peers to a Team ID and fails closed without one. Every install therefore showed a permanent "Service unavailable" with Connect disabled. The build now signs both with a real identity when one is supplied and warns loudly instead of emitting a silently non-functional bundle; the peer check itself is unchanged.
- **Web panel: the client table ignored search, status filter and pagination** — the query options were passed as a plain object, which the query library wraps in a never-re-emitting readable, freezing the key at mount. Filters changed the controls but not the rows, so an operator could act on the wrong client; on the client detail route the page could display one client while the mutations revoked another.
- **Web panel: Apply on the config page silently deleted advanced config blocks** — any advanced key absent from a textarea seeded once at page load was removed, so a `dns` or `neural` block added by the CLI meanwhile was wiped while the UI reported success. Clearing a numeric field also persisted `0` rather than omitting the key, turning "restore the default MTU" into `tun_mtu: 0`.
- **Silent failures across the web panel** — connection-key/QR fetches, session revocation and client creation swallowed every error: a failed "revoke all other sessions" looked identical to success while the session survived. The QR modal also kept the previous payload's image, so it could render one client's key (or a TOTP secret) under another's caption.
- **Android: Server Settings crashed instead of bouncing a non-admin** — `finish()` inside `onCreate` does not skip `onDestroy`, which then touched uninitialised fields, so the graceful "not connected" path became an app crash on task restore or rotation. The QS tile was also driven from a binder thread via `onRevoke`, `vpnInterface` was published without a memory barrier while written from two threads, and Keystore-backed preferences were read on the main thread during a cold start.
- **iOS/macOS: one refused Keychain write destroyed every later connection key** — the write status was discarded while keys are stored in indexed slots and a missing slot is read as end-of-list, so the next save garbage-collected the still-present tail. Failures are now reported and stop the sequence.
- **iOS: the tunnel extension could be killed by a server-declared length** — a management response buffer was sized directly from the server's declared length inside a ~50 MB jetsam limit, dropping the VPN with no diagnostic; its retry also re-issued non-idempotent requests, duplicating them and their audit entries. The management IPC additionally had no timeout, so a dead extension hung the admin UI forever with an unrecoverable form.
- **iOS/macOS: the global exit-node picker erased the setting it was meant to show** — with no getter to seed from it always rendered "(none)" and Apply sent `exit_node: null`, so an admin who opened Server Settings to change the mask and tapped Apply silently wiped the configured exit. Apply is now disabled until an explicit choice is made.
### Security

- **Role-gated in-app management dispatch** — every `MgmtRequest`, in-tunnel or over REST, is authorization-checked against the caller's `ClientRole` before it can mutate anything (`User`/`Viewer` are read-only or no-op, only `Admin` can mutate) and is per-session rate-limited; revoked clients are torn down and blocked immediately, not just marked for the next reconnect.
- **Threat-model documentation corrected to match the shipped ML/neural gate** — integrated the ML-DPI component description into the threat model and fixed the documented detection thresholds to the code's actual values (0.35 / 0.50), removing a stale/incorrect security claim.
- **Closed a `MaskUpdate` artifact-signature bypass on every client** — Android, iOS, macOS, and the web/desktop paths now enforce the operator mask-operator signature on pushed masks, and a server-derived polymorphic variant is exempt only when the transport signature proves it came from the authenticated server.
- **Client data-plane and failover hardening (audit round)** — data-plane correctness fixes plus failover hardening, a Windows kill-switch lockout fix, and leak/symlink hardening; iOS gained a Keychain-failure hard stop, token storage in the Keychain, and an IPv6-leak block; macOS added a fail-closed helper peer check and symlink-safe status reads; Windows validates the server `mask_id` before it reaches `argv` and encrypts its stored token.
- **Web panel hardening** — closed a rate-limit bypass via free JWT refresh, fixed the argon2 native-addon bundle, corrected the docker SPA path and config round-trip, hardened `X-Forwarded-For` handling, and stopped forwarding panel session credentials to the management daemon.
- **Deploy hardening** — container hardening, artifact-integrity checks, pinned image digests, and tightened secret handling.
- **Anti-replay was disabled for the first packets of every session** — the server decided a packet's key epoch by testing whether its counter appeared in the pre-ratchet tag set, but the two counter spaces overlap almost entirely after a ratchet (the ratchet restarts the counter at 0 and the new tag window is minted for the same range the outgoing one covers). Early *current*-epoch packets were therefore misclassified as old-epoch, so the main replay bookkeeping never ran: the session counter stayed at 0 and its replay bitmap stayed empty, and because a packet is only rejected as a replay when its counter is at or below that counter, those packets could be replayed for the rest of the grace window. Epoch is now decided by which key actually authenticated the packet — the only discriminator that cannot be spoofed — which closes the hole and fixes the dropped-straggler bug above with the same mechanism.
- **macOS admin-socket replies were unauthenticated** — the socket was never connected and the datagram sender was discarded, so any same-uid process could race a reply: returning `Admin` to a Viewer's role check, or handing the operator an attacker-chosen `aivpn://` key to distribute to a user. The socket is now connected to the daemon so only its datagrams are accepted.
- **iOS pasteboard no longer leaks a live connection key indefinitely** — a redeemable key was placed on the general pasteboard with no expiry, readable by every app subsequently foregrounded and broadcast via Universal Clipboard; it is now local-only and expires.

### Refactored

- **The iOS and Android tunnel cores are now one implementation** — the two mobile run loops had drifted into ~1800 lines of divergent copies of the same algorithm, so every fix had to be ported by hand and routinely was not. They are unified behind a shared `mobile_tunnel` core in `aivpn-common` parameterised by a three-method platform trait; the platform files shrank from 6266 lines to 332 and are now thin adapters. The FFI/JNI surface is byte-identical: entry-point signatures, the stop return value each platform's UI depends on, the recording-feedback JSON, and the adaptive-hint encoding all behave exactly as before. Verified on a live Android stand (handshake, PFS ratchet, both traffic directions, egress, disconnect/reconnect, and an inline rekey under sustained load, with no decrypt failures).
- **Merging the two cores resolved six behavioural divergences**, each side adopting the other's later fix: iOS gained the clock-step-tolerant RTT measurement (a backwards wall-clock step had pinned its quality score at 0), file-descriptor ownership and a checked `fcntl`, mutex-poison recovery, and the level-based keepalive clamp; Android gained the non-consuming handshake-reject peek, the full-length rekey transition window in place of a 2-second one, the mask-preference retry, and — notably — *warn* rather than *tear down the session* on a bad mid-session `ServerHello` signature, which had let a single unauthenticated packet kill a live tunnel.
- **The server's control-message dispatcher and gateway loop cadences were decomposed** — a 1377-line `handle_control_message` became a thin dispatcher over twelve per-message handlers (439 lines), and the background-loop intervals became named constants.

### Changed

- **Server config validation** — the server now tolerates unknown top-level keys in `server.json` at startup (forward-compatible) while staying strict on the management API, and added type-level config validation with management-API hardening.
- **`aivpn-web` container runs as root again** — the non-root container experiment was reverted pending the server socket-group knob; the panel ships as a root container for now (the shaping-level config select landed alongside).
- **CI: `clippy` is advisory (non-blocking)** — pending a style-lint cleanup backlog, `clippy` warnings no longer fail the pipeline; `cargo fmt --check` still gates.
- **iOS device key moved to a shared Keychain access group** — so the main app (not just the tunnel extension) can read the device public key for the SSH-install "bind to this device" flow. **Operator note:** a device that already had a key stored under the old extension-only access group generates a fresh one on its next connect, so any admin client that was previously device-bound to that device must be re-bound (re-issue its key). One-time migration effect only.

### Added — since RC2

- **Pluggable datagram transports (seam only)** — `aivpn-common::transport` introduces a `DatagramTransport` trait, the direct-UDP implementation every build has always used, a platform `SocketGuard` (`SO_MARK` on Linux, no-op elsewhere) and a name→factory registry. A build that registers nothing behaves exactly as before; a configured name that is not registered fails the connection rather than silently reverting to UDP. Behind the `transport` feature, off by default.
- **Descriptor-driven extra settings sections** — `aivpn-common::ui_ext` lets a build declare an additional settings section as *data* (a versioned JSON descriptor: typed fields with labels) that the Linux, Windows and Android UIs render generically without knowing what any field means. No descriptor, no section — which is what a stock build gets.
- **`aivpn_client::run()` as a library entry point** — the client binary's body moved into the library and now takes the transports the build can open plus a socket guard. The shipped binary passes none and behaves as before.
- **Public-tree hygiene and self-containment gates** — `make hygiene-gate` (case-insensitive vocabulary gate over the distributed tree) and `make selfcontained` (no manifest may reference a path outside the repository; build and test with no extra feature), both wired into CI.

### Fixed — since RC2

- **The kill-switch blocked the client's own traffic when the server address was IPv6** — the nftables bypass rule was built with a hard-coded `ip` family, so with an IPv6 server it matched no packet at all and enabling the kill-switch cut the tunnel it was meant to protect. The family is now selected from the address and covered by tests.
- **A closed control channel spun the upload loop at 100 % CPU** — a closed channel's `recv()` resolves immediately on every poll, so that arm kept winning the `select!` for the rest of the session. It now terminates the loop like a closed data channel does.
- **Two inbound-control paths silently ignored unknown messages** — the triplicated `ControlPayload` handling on the desktop and both mobile cores is now an exhaustive match, which surfaced and fixed two paths that dropped messages they should have acted on.
- **tc/eBPF QoS program never actually ran**, plus skb/socket hardening in the kernel data path.
- **Upstream fixes 1.0.2 – 1.0.5 carried over** — TUN-duplicate ownership by the session (with a two-phase fd release that closes a reuse window the upstream fix leaves open), descriptor-mask condemnation on a dead data plane, Docker's `FORWARD DROP` silencing nftables-only rules, one mask per session on mobile, handshake framing at the mask's own header length, handshake cooldown keyed on the full socket address with live sessions exempt, and a guard against shipping a debug APK as a release artifact.

### Security — since RC2

- **The upstream legacy wire-layout compatibility is deliberately absent** — `apply_legacy_key_scheme` collapses `session_key_s2c` into `session_key`, and the data plane's nonce is a little-endian counter with no direction separator, both starting at zero. That reuses a `(key, nonce)` pair in ChaCha20-Poly1305 from the very first packet: the keystream cancels in the XOR of two ciphertexts and the Poly1305 one-time key is reused. The feature does not work without the collapse, so it is removed in full rather than half-kept. A safe route remains open for the future — keep directional keys and separate the directions into non-overlapping counter ranges — and would have to be proven against a live old server. The same prohibition was already written down in `site_sync.rs`.

### Refactored — since RC2

- **Pool sync redesigned as "the server dials its peer as a masked pool client"** (PSK derived via `HKDF(sync_key)`), with bidirectional anti-entropy on last-writer-wins plus tombstone merge. It unifies what used to be three separate mechanisms: `pool_sync`, `chain_forward` and `site_sync`.
- **The largest modules were decomposed into focused submodules, behaviour unchanged** — `gateway.rs`, `mgmt_service`, `client_db` and the server `main` on the server side; `client.rs` on the desktop; the Linux and Windows GUI god-files. Loop cadences became named constants and the `handle_control_message` god-function became per-message handlers.
- **The two mobile tunnels became one** — iOS and Android now share `aivpn-common::mobile_tunnel` behind a `PlatformIo` trait (`run_tunnel_generic`), collapsing roughly 6 200 duplicated lines into about 330 and eliminating six behavioural divergences between the platforms, including one where a forged `ServerHello` killed the session on only one of them.

## [1.0.5] - 2026-08-10

### Fixed

- **Old clients discarded the `ServerHello` and reconnected forever** — a pre-Variant-A client compares the `ClientNetworkConfig` version byte for EQUALITY and drops the whole message when it differs. Wire v2 appended a keepalive byte and bumped that version, so the handshake completed on the server, the `ServerHello` went out, and the client silently threw it away: no ratchet, no data, another handshake minutes later, forever. Caught on a live server — the same client handshaking from the same source port every few minutes, answered each time, never sending a packet in between. The server now emits the v1 form to a peer flagged `legacy_peer`, which costs only the keepalive hint such a client never had. On production this took one looping client from 37 handshakes per 5 minutes to one per 10 minutes, and uplink decrypt failures from 2567 to zero.
- **One client's stale packets locked out its whole home network** — the handshake-failure cooldown was keyed by source IP, and every device behind a home NAT shares one. When a single phone retried with stale keys the server blocked handshakes from that IP for up to 16 seconds, taking every other client behind the same router with it; two clients on one router were observed looping in lockstep, neither able to reconnect. Worse, the failure that armed the cooldown was often not a failure: a packet from a live session reaches the handshake path whenever the tag lookup misses (the tag window drifted, or the global rescan budget was spent that second), and the server then tried it as a handshake, found no matching client, and locked the peer out while it kept sending. Cooldowns are now keyed by the full peer address, and a peer that still has a session is exempt from both the block and the accounting. Spoofed-source floods stay bounded by the global handshake-scan budget, which varying ports does not evade.

## [1.0.4] - 2026-08-10

### Fixed

- **Old clients connected, then dropped into an endless reconnect** — the handshake put a pre-Variant-A peer into legacy compatibility mode (single, non-directional session key), but that was a one-shot fixup of the keys present at that moment. The inline rekey runs every couple of minutes and installs freshly derived keys, so the downlink silently switched to a directional S2C key such a client cannot decrypt: its session went deaf, the watchdog fired, and it handshaked again. Measured on a live server: 115 accepted legacy handshakes from one client in 40 minutes, each followed by silence. The session now carries an explicit `legacy_peer` flag that every key derivation honours, and a mask pushed to such a peer keeps the tag-prefix layout so a `MaskUpdate` cannot diverge the framing.
- **Desktop clients could never use the legacy fallback** — it is a two-part contract (tag-prefix framing AND the single session key), and only the mobile cores implemented both. The desktop client, which the macOS and Windows GUIs run as their tunnel process, had neither: it could not reach a server older than the embedded-tag change, and once a server answered it in legacy compatibility mode it could not decrypt its own `ServerHello` — handshake timeout, reconnect, forever. It now mirrors the mobile ladder, collapsing the directional split for such a session at every key derivation (zero-RTT, PFS ratchet, inline rekey).

## [1.0.3] - 2026-08-08

### Fixed

- **Roughly one connection key in five could never connect (#68, part of #70)** — the client framed its handshake at the protocol default header length (20 bytes), while the server reads the embedded ephemeral key at the `eph_pub_offset` of the mask it matched. For `quic_https_v2` that offset is 14, so the key landed six bytes past where the server looked: wrong DH input, wrong session keys, and a tag mismatch against every candidate of every registered client — permanently. The PSK selects the preset (`blake3(psk)[0] % 5`), so this bricked about one issued key in five at random: `--show-client` handed out a key the app could never use, and the app sat in an endless reconnect ("hangs after entering the key"). The other four presets have a 20-byte header, where the wrong value happens to equal the right one, which is why it went unnoticed. Both mobile cores now frame with the handshake mask's own length and decode the `ServerHello` at whichever length actually parses.
- **The data plane could use a different mask than the handshake** — the handshake mask and the data mask were resolved by two separate calls. The server pushes fresh bootstrap descriptors as soon as the session is up, so the second call could see a newer descriptor set and pick a different candidate; if its header length differed, the server decrypted every uplink packet at the wrong offset while the resonance tag still matched, leaving the tunnel "connected" and carrying nothing. The session now reuses the exact mask the handshake was accepted with.
- **Server: client traffic was dropped on any host with Docker installed** — Docker sets `iptables -P FORWARD DROP`, and netfilter evaluates the legacy iptables FORWARD hook independently of the nftables ruleset, so a packet must be accepted by both. With the nftables backend selected, client packets reached the server's tun and never left it. The accepts are now mirrored into iptables (into `DOCKER-USER` when present, which Docker never flushes) whenever the FORWARD policy is DROP, and removed on teardown. Hosts without Docker are unaffected.
- **`make android` could publish a debug APK** — with no signing material configured the build silently fell back to `assembleDebug`, and that build shipped as the release asset in 1.0.0 and 1.0.1. A debug APK is `android:debuggable`, so anyone with adb access could attach to the VPN process and read session keys out of its memory, and its signature is the public Android debug key. The build now fails with an explanation instead; `AIVPN_ALLOW_DEBUG_APK=1` restores the old behaviour for local testing only.

## [1.0.2] - 2026-08-05

### Fixed

- **Android: tunnel connected but carried no traffic, only a reinstall helped (#71, #70)** — the Rust core duplicates the Android TUN descriptor, and those duplicates outlived the interface: Kotlin closes its `ParcelFileDescriptor` on disconnect and gives the native call 3 s to unwind, so a slower unwind left the tun device alive as a zombie still holding the VPN address. The next session established a *second* tun with the same address, app packets were routed into the dead one nobody reads, and the tunnel reported "connected" while the server saw keepalives and not one data packet. Caught on a device as `tun0` DOWN holding the VPN address next to a live `tun1`. The session now owns both duplicates (the `AsyncFd`s only borrow them), so stopping the tunnel destroys the device immediately; both closers take the descriptor with `swap(-1)`, so it is closed exactly once. After a disconnect the process holds zero tun descriptors and the device zero tun interfaces.
- **Android: a cached bootstrap descriptor could strand the data plane** — a session that completes the handshake but never receives a single downlink data packet now discards its cached descriptors (in-process and app-persisted, the verdict surviving an app restart) and pins the next attempt to a builtin preset. Narrowly scoped: a healthy covert session that merely stalls on a network change keeps its descriptors and just reconnects.
- **Server: an uplink packet that failed to decrypt could wedge the packet loop** — the diagnostic path re-locked the session mutex already held by the enclosing block (`parking_lot` is not reentrant), deadlocking the worker and, with the lock never released, every other session with it.

### Added

- **Interoperability with servers and clients from before the embedded-tag layout** — an app updated past that change could not reach an older server at all, and an upgraded server could not serve an older app; both sides retried forever. Clients now fall back to the legacy tag-prefix layout (and its single, non-directional session key) after repeated failed handshakes, and servers accept that layout in a second handshake pass that runs only when the modern pass finds nothing. Upgrade order no longer matters — see "Version Compatibility" in the README.

### Security

- **Per-direction AEAD keys — ChaCha20-Poly1305 nonce reuse eliminated.** Both traffic directions previously encrypted under the same session key with independently advancing nonce counters, so counter overlap reused a (key, nonce) pair across directions — a real confidentiality break. Client→server and server→client now derive separate directional keys; pool/site/chain server-to-server sync uses per-direction keys too, and directional key derivation now *fails closed* (returns an error) if the two peer ids compare equal instead of silently deriving identical keystreams both ways.
- **iOS core: nonce reuse on Shutdown and a ghost session** — the iOS tunnel sent Shutdown through its own encryption path that reused a nonce and left a half-dead session registered on the server; it now uses the same control-plane transmit path as Android and desktop.
- **Kernel module: rmmod use-after-free and resource lifetime** — the UDP receive hook was never uninstalled on module unload, leaving the socket's `sk_data_ready` pointing into freed module memory (use-after-free on the next packet); unload now restores the socket callbacks first, the held TUN device reference is released, `SET_UDP_SOCK` is idempotent (no recursive re-hook), both crypto transforms are freed on every path, and anti-replay uses the WireGuard-ordered window algorithm. Kernel-consumed RX skbs also release their UDP receive-memory charge (an `sk_rmem_alloc` leak that eventually stalled the socket with kernel WARNs), and reused skbs are scrubbed (`skb_scrub_packet` + checksum reset) before TUN injection so stale conntrack/dst/checksum state never leaks into the host stack.
- **macOS: privileged helper pins peers by code signature** — the helper now validates the connecting process's audit token against the signed app's code-signing requirement and verifies the client PID's identity, instead of trusting the uid alone. (The Team ID placeholder must be set to the real signing team for production builds.)
- **Web: login timing oracle closed + TOTP codes are single-use** — login performs an equal-cost Argon2 verification even for nonexistent users and passkey-only accounts, so response timing no longer reveals whether an account exists; a TOTP code can no longer be replayed within its time step (`totp_last_step` tracking); the refresh cookie uses the `__Host-` prefix on HTTPS origins; refresh-token rotation gained a small reuse-grace window while login rate-limiting counts only failures; concurrent SSE streams are capped per user with a bounded lifetime; stored User-Agent strings are length-capped.
- **Bootstrap fetch SSRF guard on every client** — bootstrap descriptor URLs are now *resolved* and rejected when they point at private, loopback, or link-local addresses (the previous string-prefix check was bypassable via DNS), the guard is re-applied on every redirect hop, and response bodies are size-capped; applied on desktop, Android, and iOS.
- **Android: secure storage no longer self-destructs on transient errors** — any exception while opening `EncryptedSharedPreferences` (including a locked user profile or a transient Keystore outage) wiped the store, destroying every saved connection profile; the wipe now fires only on genuine corruption while the device is unlocked.
- **Connection keys redacted from logs and process lists** — the Windows client wrote its full command line (containing the PSK-bearing connection key) to its startup log; desktop GUIs now pass the connection key and Telegram token to the client via environment variables instead of argv, so they are invisible to `ps` and never logged.
- **Anti-replay and session hardening** — the anti-replay window widened to 512 packets with ±2 windows of handshake clock-skew tolerance, tags older than the replay bitmap window are rejected outright, and counter-recovery brute force is bounded to ±2048 steps.
- **IPv6 leak fixes** — Android now routes IPv6 (`::/0`) through the VPN so dual-stack apps can't bypass the tunnel over v6, and the Linux full-tunnel client blackholes IPv6 when the tunnel itself is IPv4-only.
- **iOS: device key stored ThisDeviceOnly** — the device-binding key no longer syncs to other devices via iCloud Keychain.
- **Web RBAC and proxy hardening** — viewer-role checks canonicalize the request path before matching (no encoded-slash bypass), SSE is gated by role, viewer access is enforced through a fail-closed allowlist, proxied request bodies are size-capped, metrics/events routes are rate-limited, placeholder secrets are rejected at startup, and `requireReadAccess` failures return proper 401/403 instead of 500.
- **Local file hygiene (Linux)** — the GUI's `settings.json` (contains the Telegram token) is written `0600` atomically; stats/quality/recording exchange files are only trusted when owned by the current user or root (symlink/TOCTOU guarded); the client admin-token directory stays off the shared `/tmp`; the bootstrap cache directory is created `0700`; the management API socket is staged in a private directory instead of flipping the process umask.
- **Mobile FFI panic containment** — panics crossing the tunnel FFI boundary are caught on Android and iOS instead of aborting the host app.
- **Unsigned network bootstrap descriptors rejected** — a client without a configured signing key no longer accepts network-fetched bootstrap descriptors at all (previously accepted unverified).
- **Never log session key material.** The client logged the resonance `tag_secret` at `RUST_LOG=debug`, and the server logged the DH shared secret, PSK, and `tag_secret` at `trace`. Both levels are operator-selectable, so any log file or support bundle could recover the exact secret that keeps a session unlinkable to a passive observer. These lines are removed; only non-sensitive breadcrumbs remain (the public ephemeral key is still logged).
- **Web: block the `viewer` role from `GET /api/v1/bootstrap/export`.** The signed bootstrap descriptor set is an operator secret and the backend handler is documented admin-only, but the proxy's viewer blocklist omitted `/bootstrap` and the export is a `GET` (so the write-only guard did not cover it). Any authenticated viewer could download it.
- **Kill-switch (Linux/nftables): flush stale accept rules on re-activation.** The nftables path used idempotent `add table`/`add chain` and then appended the loopback/tun/server-IP accept rules without flushing first, so every reconnect (new random TUN name) or pool failover (new server IP) permanently appended another `ip daddr <old-server-ip> accept` rule — a real leak letting host processes reach a previous node unblocked. The chain is now flushed before rules are re-added, mirroring the iptables fallback.
- **Neural: harden per-mask calibration against poisoning.** The adaptive compromise threshold folded every session's MSE into a shared per-mask baseline unconditionally, so a client with a valid PSK could stream anomalous traffic to inflate the threshold and disable DPI-compromise auto-rotation for every other client on that mask. Calibration now rejects gross outliers (>8σ) and clamps each sample's magnitude; detection still uses the raw MSE.
- **Server: cheap handshake tag pre-check before `create_session` (DoS hardening).** The pre-auth handshake scan ran the full `create_session` (two DHs, an Ed25519 signature, ~767 keyed hashes, three O(session-count) scans) for every registered-client × candidate-mask pair before checking the tag, so a spoofed-source flood scaled CPU cost with the client-database size. A one-DH tag pre-check now gates session creation.
- **Hostile mask cannot crash clients** — the GMM/parametric samplers now validate the component count (division-based length check + cap) and clamp sampled inter-arrival times, so a crafted `MaskUpdate` can no longer integer-overflow an index (OOB panic) or emit an IAT that panics `Duration::from_secs_f64`. Header-field widths are clamped to an MTU (no allocation abort) and `ClientNetworkConfig` prefix lengths are range-checked (no netmask-shift underflow).
- **Full mask signature coverage** — `MaskProfile` signatures now authenticate the entire profile (`header_spec`, `tag_offset`, `spoof_protocol`, distributions, FSM), not just a handful of fields, so an attacker cannot repoint the wire layout or tag position while keeping a valid signature. (Breaking: masks signed by pre-0.10 builds no longer verify.)
- **Pre-auth handshake DoS bounded** — a global, source-IP-independent budget caps the per-client × per-mask handshake candidate scan, so a spoofed-source UDP flood can no longer force millions of DH/tag operations per packet; the default per-IP packet rate limit dropped from 50000 to 5000.
- **Telemetry-driven mask compromise requires corroboration** — client-reported `TelemetryResponse` can no longer let a single authenticated client mark a shared mask compromised for everyone; a mask is only rotated on client telemetry when ≥3 distinct reporters corroborate. Server-measured neural-resonance compromise is unaffected.
- **Client tag-search DoS bounded** — the receive-window forward tag search is capped so a garbage-UDP flood at a client's ip:port can't force ~13k keyed hashes per packet.
- **Elevated binary resolution hardened** — the Linux/Windows GUIs resolve `aivpn-client` / `aivpn-ip-helper` only by a trusted absolute path (never a bare relative name or `PATH`), closing a binary-planting → privilege-escalation vector.
- **macOS: helper survives reboot + peer-cred check** — the privileged helper's LaunchDaemon no longer depends on the volatile `/var/run` (which is wiped on reboot, previously leaving the app stuck on "service unavailable"); logs moved to `/var/log`. The helper also verifies the connecting peer's uid (`getpeereid`) is root or the console user.
- **iOS server-signature verification** — iOS now passes the operator's ed25519 signing key to the tunnel (was hardcoded to skip verification), reaching parity with desktop/macOS.
- **Web panel** — X-Forwarded-For is trusted only behind a configured proxy (`AIVPN_WEB_TRUST_PROXY`), preventing rate-limit bypass and audit-IP forgery; the SSE access token is redacted from request logs; OIDC exclusive mode now actually disables password login; access tokens moved out of `localStorage`; usernameless passkey login fixed; login/passkey enumeration reduced.
- **Management API socket race** — the Unix control socket is created under a restrictive umask so it is never momentarily connectable by other local users before its `0600` mode is set.
- **Linux GUI key storage** — connection keys (which contain the PSK) are written `0600` via an atomic temp-file rename instead of a world-readable non-atomic write.

### Fixed

- **A lost inline-rekey `KeyRotate` self-heals with zero reconnects (server + all clients).** In-flight PFS rekey previously sent `KeyRotate` exactly once; if that packet was lost, the server sat on new keys while the client kept the old ones — an irrecoverable desync ending in a ~35 s watchdog reconnect. The server now retransmits an unacknowledged `KeyRotate` on a short (~4 s, below the client's RX-silence watchdog) timer reusing the same rekey keypair, the rekey-ack wait is bounded so a dead upload task can't hang the receive loop, and uplink/downlink packet counters stay monotonic across the rekey (no nonce regression). Live-verified with injected packet loss: zero reconnects. Ported to desktop, iOS, and Android.
- **Self-healing downlink MDH-length discovery (all clients)** — after a missed mask update, downlink packets framed at a different mask-derived-header length became undecodable and the session died; clients now track every MDH length ever seen for the session, the shared decoder tries all of them, and the active framing is re-discovered automatically.
- **Pool/site/chain sync framing is mask-independent** — server-to-server sync packets were framed against the sending node's primary mask while the receiver derived the offset from *its own* primary mask; with embedded-tag masks (8 of 11 bundled) the AEAD never verified, so pool client databases silently never converged. Peer sync (pool sync, multi-site sync, chain forwarding) now uses a fixed cluster framing layout independent of any mask, plus a deterministic primary-mask choice; verified live on a two-node pool running embedded-tag masks.
- **Server: inline-rekey `KeyRotate` framed with the session's own mask** (it was framed with the primary mask — undecodable for sessions running a different one), and the server no longer auto-switches an established session onto a newly-set runtime mask mid-wire (which broke framing mid-session).
- **Server: rekey grace and session eviction fixes** — the rekey/ratchet grace window now scales with the measured client RTT instead of a fixed 2 s; grace-period tags stay in the tag map so post-ratchet in-flight packets aren't throttled away by the 20/s fallback-scan cap; pool/site cluster sessions are excluded from idle eviction (they were evicted after a quiet hour and never recreated, silently killing sync); and the pre-auth fallback scan is bounded.
- **Client UDP receive buffers sized for large control packets (all clients)** — 1500-byte buffers truncated large control messages (mask catalogs, bootstrap descriptor updates), which then failed to decrypt; handshake and data-path receive buffers enlarged on desktop, iOS, and Android.
- **Keepalive vs NAT timeout (all clients)** — adaptive keepalive intervals could exceed typical carrier-NAT UDP mapping lifetimes, silently killing the return path; keepalive is now capped under the NAT ceiling with asymmetric silence detection, Android's `AdaptiveHint` cap now clamps to the NAT ceiling rather than the 4 s floor, and iOS/Android re-arm the keepalive timer when an `AdaptiveHint` arrives.
- **Desktop first-contact handshake bounded to ~10 s** — a dead or filtered server previously kept the first connection attempt spinning far longer before the client tried the next bootstrap option.
- **Client resilience fixes** — `EPERM` on send (kill-switch/firewall races) is treated as transient instead of killing the session; the `ServerHello` keepalive warm-up burst only fires on a real reconnect; `ever_connected` is set on `ServerHello` rather than the zero-RTT transition (fixing reconnect/backoff logic).
- **Client data-path and teardown hardening (desktop)** — the SOCKS5 downlink queue is bounded (a stalled consumer could grow it without limit), the RX watchdog counts only validated packets (garbage UDP could keep a dead session looking alive), the upload task is awaited on shutdown, and the never-functional client-side kernel/XDP wiring and dead adaptive-MTU step-down were removed.
- **Server: management API hardening** — serialization errors return 500 instead of panicking the API task, uploaded masks are validated as real `MaskProfile`s (signature included) before entering the store, and `broadcast_mask_update` no longer logs a broadcast it didn't perform.
- **Server: auto-mask recording captures the inner L7 header** — recorded header templates were built from tunnel ciphertext instead of the decrypted inner packet, producing garbage mask headers.
- **Web: PostgreSQL migrations actually run** — the Drizzle migration journal was missing, so schema migrations (including the TOTP one-time-use column) never applied on Postgres; the DDL is now applied inline against the existing migration table. Also: the sliding-window rate limiter is exact, token refresh is coalesced across tabs, and SSE authentication uses one-time tickets.
- **Linux GUI: kill-switch is actually cleared on disconnect/quit** — the GUI SIGKILLed the client, so the client's own kill-switch teardown never ran and the host stayed firewalled off the network; it now SIGTERMs and waits. A follow-up regression was also fixed: on reconnect the old client's late teardown (0.5–3 s after SIGTERM) could tear down the *new* session's routes and kill-switch — reconnect now waits for the old process to be fully reaped first. Quality/stats files are read from `/var/run/aivpn`, preferring the freshest copy.
- **Windows GUI: kill-switch clear no longer blocks the UI thread** (the window froze for the duration of the `netsh` calls).
- **Android: an invalid connection key is fatal, not an infinite retry** — the VPN service used a duplicate, weaker key parser than the UI, so a key the UI would reject (or an invalid explicit server port) put the service into an endless reconnect loop; it now uses the shared validated parser and enters a terminal error state on fatal config problems. Also: survives Direct Boot (no crash before first unlock), honors the foreground-service contract, always-on VPN restored, a missing native library is reported instead of crashing, profile loss and a false "connected" UI state fixed, `POST_NOTIFICATIONS` requested at runtime on Android 13+, and the dead pure-Kotlin crypto fallback was removed.
- **iOS: tunnel lifecycle hardening** — a stop request during tunnel setup is honored (previously the extension could get stuck connecting with no way out), the tunnel calls `cancelTunnelWithError` when the Rust core dies (previously a silent traffic blackhole), a double-close of a recycled file descriptor is guarded, an inbound-write TOCTOU race is fixed, `ServerHello` network config and the server-pushed keepalive are applied instead of discarded, the handshake receive buffer was enlarged, and a new `preferred_mask` FFI parameter lets the app shape the opening burst.
- **iOS/Android: `Shutdown` and `BootstrapDescriptorUpdate` control messages are handled** — mobile clients previously ignored both (a server-initiated shutdown looked like a network failure, and mobile never refreshed bootstrap descriptors); descriptors are no longer logged as "validated" before validation, both mobile cores fixed an fd use-after-close race, and mobile clamps server-pushed `FeedbackConfig` tuning like desktop.
- **macOS/iOS: bare-base64 connection keys accepted** — keys pasted without the `aivpn://` prefix now parse everywhere; the macOS helper and iOS tunnel bridge got matching input hardening.
- **Kernel egress: GSO packets are linearized (and GSO skipped) before `skb_checksum_help`** — eliminated a `skb_warn_bad_offload` kernel warning under load on the downlink fast path.
- **Common: hostile-input hardening** — `SizeIatGmm2d` component counts are guarded before the usize cast, sampled joint-GMM inter-arrival times are clamped before `Duration` conversion (a hostile mask could panic the client), and control-packet length arithmetic is overflow-safe on 32-bit targets.
- **Linux GUI polish** — separator/toggle layout fixes in the connection panel; the AppImage build works without a preinstalled `appimagetool`; the iOS mask-catalog FFI getters are declared in `aivpn_core.h` (build fix).
- **Client: recover from an unmatchable cached bootstrap descriptor.** A cached descriptor signed by a server whose key was later rotated (or an epoch the server no longer retains) yields a handshake mask the server cannot reproduce, so every handshake failed with a tag mismatch and the client looped forever. After three consecutive dead handshakes the client now falls back to the built-in default mask, which every server matches.
- **Web: adding/editing a client no longer returns HTTP 415.** The API proxy built its forward-header map with `Object.entries()` over a Web `Headers` object, which yields nothing, so it dropped every request header (`Content-Type`, `Authorization`) — `POST`/`PUT` bodies reached the backend without a content type and were rejected. Headers are now iterated correctly.
- **Web: honor `AIVPN_WEB_ADMIN_PASSWORD`.** The variable was documented but ignored; the first-run bootstrap always generated a random password. It is now used to seed the initial `admin` user when set.
- **Web: the panel boots from source instead of the broken bundle.** `bun build` inlined the `@node-rs/argon2` native addon into `dist/index.js`, which then failed to load at runtime, so the documented start path and the Docker image never booted. The Docker image and start script now run `server/src/index.ts` directly.
- **Server: pre-ratchet anti-replay could falsely drop packets.** The 256-bit pre-ratchet replay bitmap aliased counters 256 apart within the 511-wide tag window, so a legitimate in-flight packet could be rejected as a replay during the 2-second post-ratchet grace window. Replaced with a per-counter set that cannot alias.
- **Client: the adaptive monitor survives a poisoned mutex** (adopts the crate-wide `unwrap_or_else(|e| e.into_inner())` pattern instead of `unwrap()`).
- **Security (CRITICAL): Android anti-replay bypass** — `searchEnd = maxOf(256L, recvHighest+257L)` always searched from counter 0 for early packets, allowing replay of counter-0 packets throughout the session; guarded with `if (recvHighest < 0L) 256L else recvHighest + 257L`.
- **Security (CRITICAL): Android padding OOB read** — bounds check in `processServerHello` was inverted; crafted packets could trigger a read beyond the decrypted buffer.
- **Security (CRITICAL): Android X25519 division-by-zero** — `z2.modInverse(FIELD_P)` threw `ArithmeticException` on low-order point inputs; guard added before inversion.
- **Security (CRITICAL): iOS Keychain access group missing** — `kSecAttrAccessGroup` never set on any Keychain call; the tunnel extension could not read keys written by the main app on independent process restart.
- **Security (CRITICAL): iOS `canRecord` hardcoded `true`** — recording UI was shown to all users; now derived from `key.canRecord ?? false` at tunnel start.
- **Security: Android Blake3 keyed-hash input size not enforced** — `require(data.size <= 1024)` added.
- **Security: Server pre-ratchet bitmap aliasing** — `counter.min(255)` mapped all counters > 255 to bit 255, falsely rejecting valid in-flight packets as replays during the PFS ratchet grace window; fixed with `counter % 256`.
- **Security: iOS `SecRandomCopyBytes` return value unchecked** — RNG failure left device key bytes all-zero silently; guard added.
- **Web panel: `ReferenceError: now is not defined` (PostgreSQL)** — undefined `now` variable in `auth/middleware.ts` and SSE `/web/events` PostgreSQL path crashed every authenticated request and SSE connection.

### Changed

- **The default `server` build target is now the full-featured build** (management API, metrics, neural, passive distribution); a new `server-tiny` target produces the previous minimal binary.
- **PFS rekey byte threshold raised 1 MB → 64 MB** — rekeying every megabyte measurably throttled sustained transfers for no practical security gain; time-based rotation is unchanged.
- **IPFS removed as a bootstrap-descriptor distribution channel on all platforms** — the remaining channels are CDN/S3, GitHub, and Telegram; `KeyRotate` handling was made idempotent as part of the same cleanup.
